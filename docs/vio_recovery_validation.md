# VIO 恢复验证（2026-09-27）

本次修改解决短暂 VIO 跳变直接导致 Offboard 心跳中断的问题。当前真机仅有
D435i 与飞控，没有独立水平定位备份；本报告不承诺持续定位丢失时继续安全留空。

## 实现

- VIO 突跳先进入有界隔离，连续检查候选位置与速度一致性、位移、姿态和时间。
- 重新接受真实 VIO 数据时递增 EV `reset_counter`，不平滑伪造位置、不回灌 PX4 位置。
- 控制器在 PX4 位置新鲜且有效时保持 Offboard 心跳与固定悬停目标。
- PX4 位置/高度/航向重置时，用对应 reset delta 调整悬停目标。
- 定位恢复后进入 `RECOVERY_HOLD`，操作员调用 `start_mission` 后重新打点。
- 持续失效、恢复超时、缺少可靠 PX4 位置或丢失重置增量时仍保留故障保护。
- OpenVINS 仿真跟踪限流从 30 改为 40 Hz，避免丢弃 Gazebo 32 ms 间隔的相机帧。
  相机仍为 30 Hz，尚不能据此断言所有估计突跳均已消除。
- PX4 SITL 后台启动使用 `-d`，避免没有交互输入时重复打印 `pxh>` 并消耗 CPU/磁盘。

2026-09-27 两次用户复现进一步暴露了长间隔恢复错误：OpenVINS 输出缺口为
2.092/2.124 s，原桥接器在首个新样本到来时把它与 2 s 的恢复等待上限相比较，
导致所有后续样本都无法进入稳定窗口。修复后，首个新样本与上次正常输出之间的
允许间隔单独限制为 3 s；样本恢复后的连续性检查仍为 2 s。长间隔允许最多
2.5 m 的预测偏差及 90° 的姿态变化，然后要求 0.5 s 连续轨迹并通知 PX4 里程计
重置。控制器等待上限改为 5 s，PX4 位置失效仍立即退出悬停。该阈值用于隔离后
重新建立坐标系，不代表 2.5 m 的定位误差可直接用于继续导航；必须人工重新确认地图。

## 2.124 s 输出缺口闭环复验

在同一 PX4 1.14.3 + Gazebo 仿真栈里，悬停后暂停送往桥接器的 OpenVINS 里程计
2.124 s，随后持续施加 1.44 m 的坐标偏移。测试中继仅在独立测试启动文件里启用，
不会影响正常启动入口。结果位于运行工作区的 `flight_bags/recovery_validation/`：
`sitl_long_gap_result.json`、`long_gap_ulog_validation.json`、
`long_gap_algorithm.log`、`long_gap_probe.log`。

| 仿真时间 | 事件 |
| --- | --- |
| 29.200 s | MISSION，悬停 |
| 31.204 s | 开始停发，恢复后里程计持续偏移 1.44 m |
| 31.600 s | VIO_HOLD |
| 约 33.3 s | 桥接器开始检查新的连续样本；日志显示缺口 2.128 s、跳变 1.458 m |
| 约 34.0 s | 连续性检查通过，送出 EV reset counter |
| 35.000 s | RECOVERY_HOLD |
| 37.004 s | 测试工具明确请求继续任务 |
| 37.100 s | MISSION |
| 40.104 s | 测试工具主动请求降落 |

任务暂停期间 Offboard 心跳最大间隔 0.100 s；PX4 估计高度范围
1.9223–1.9765 m。ULog 在注入到主动降落的窗口内记录 `nav_state=14`、
`failsafe=0`、`offboard_control_signal_lost=0`、`local_position_invalid=0`。
旧逻辑在同类两次复现中分别出现 2.092/2.124 s 输出缺口，然后控制器进入
FAULT。这轮验证说明软件中的错误门槛已经修复；它仍不能证明 OpenVINS 为何
原本会停发，因此下一次原生故障需继续录双目、IMU、VIO 与桥接诊断。

## 原始故障录包回放

输入：`flight_bags/vio_fault_20260926_193536`，仅离线调用桥接回调，未向 PX4 发消息。

| 仿真时间 | 结果 |
| --- | --- |
| 182.076 s | 0.453 m 位置突跳，开始隔离 |
| 182.708 s | 连续性检查通过，恢复真实 VIO 输出，reset counter 变为 1 |

原始 3226 帧按本机 OpenVINS `ROS2Visualizer.cpp` 的限流条件计算：30 Hz 上限保留
1871 帧（17.57 Hz），40 Hz 上限保留 3226 帧（30.30 Hz）。这是输入接收率计算，
不能代替重新运行 OpenVINS 后的定位精度评估。

## 覆盖边界

自动回归覆盖恢复等待、固定悬停、显式恢复、健康状态闪烁、失效位置、恢复超时、
重置计数跳跃、坏候选打断稳定窗口、规划器清除旧目标等情况。
闭环实验覆盖悬停状态的单次持续平移突跳；移动中、强旋转、长期遮挡和真机
仍需继续验证。地图与场地的绝对对齐在恢复后需要检查，稳定输出并不证明
绝对位置准确。本轮没有增加不存在的光流、UWB 或其他独立传感器。
